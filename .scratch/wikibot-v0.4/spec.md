# wikiBot v0.4 实施规格

状态：in-progress（实现与验收分列）；用户已通过 implement 指令确认测试边界、任务粒度与依赖。用户已选择仅保存为本地 Markdown，不发布到外部追踪器。日期：2026-09-27。

## Problem Statement

业务成员需要完成广告接入与配置准备，但现有知识散落、流程适用条件不清，重复问题依赖专家解答。普通搜索或自由生成容易漏掉前置条件、混用客户信息或沿用已失效知识；管理员也缺少从反馈到来源更正、复核发布的可追溯闭环。

首个领域覆盖新渠道接入、腾讯广告新增代理商、腾讯 RTA 新增策略。业务目标是让成员依照明确、可引用的指导自行完成操作，并减少专家重复答疑。系统只提供知识指导，不读取或改变广告系统实际状态。

## Solution

建立复用现有 llm-wiki skills 维护知识库的领域 Bot，以经过复核的不可变知识版本提供企业微信与网页问答。知识包由 pages、金样例问答 cases 和发布配置 config 组成；服务端检索已发布页面，公司模型单次组织有依据的自由文本回答，引用校验并绑定固定知识版本。访问资格、领域角色、回答视角及解释深度分别建模。

普通成员可问答、主动登记问题、反馈答案并跟踪本人工单；知识管理员可处理领域工单、通过 bot 发起修订，将更正写回唯一维护源，经最终快照复核和评估后发布。知识发布、生成完成、渠道交付、用户确认解决分别记录。

分两道交付门槛：受控试点交付一个广告领域、三个流程批准范围内的网页与企微单聊及维护闭环；完整范围继续验证群聊、完整来源与静态附件、工单高级交互及第二个非广告领域。两道门槛均要求其启用范围具备授权、基于证据的回答质量、发布一致性与基本恢复能力。

2026-09-26 用户再次明确第一阶段支持企业微信机器人，并提供 Bot 标识与 Secret 作为接入输入。企微单聊问答、基本工单/反馈及管理员维护入口属于首阶段必需交付；网页与群聊的既定分期不因补充凭据而改变。凭据值不写入规格或仓库。

10. 作为知识管理员，我希望金样例对照预期判定并复核知识缺口和冲突，以便发布前发现错误回答。

41. 作为领域成员，我希望已收到的模型待复核答案仍可追溯并显著标记，以便理解其验证状态。
42. 作为平台负责人，我希望未交付的待复核正文不被重连或恢复补发，以便落实暂停交付的决定。

47. 作为知识维护者，我希望改名、链接、来源摘录和白名单静态附件能正确往返，以便知识引用保持稳定。

49. 作为试点负责人，我希望在固定支持范围与负载下查看真实质量、时延和交付结果，以便作出上线决定。
50. 作为业务负责人，我希望比较自行完成操作、专家答疑负担和工单复发情况，以便评价实际效果。

## Implementation Decisions

### 已接受的业务与架构约束

- 采用 TypeScript 模块化服务，入口与异步执行按部署需要分进程；关系数据库持久化业务状态，不可变内容放受控存储。同库任务与 outbox 支持可恢复操作。
- 公司批准模型通过 ModelGateway 隔离，当前采用固定版本 @earendil-works/pi-ai 传输；真实最小调用已有证据，完整契约与业务质量仍待验收。模型服务、企微和 llm_wiki 的既有能力不能替代本项目领域契约。
- 2026-09-26 用户补充智谱 CC 配置：Anthropic 兼容入口为 https://open.bigmodel.cn/api/anthropic，常规模型映射 glm-5.3[1m]，快速模型映射 glm-5.3-flash[1m]。阶段 0 据此验证直接 API 模型 ID、鉴权、上下文与配额；CC 的别名、[1m]、自动压缩及 50 分钟客户端超时不直接成为在线服务参数。模型仍须经独立评估与配置发布，不因提供两档映射自动启用动态路由。凭据不进入文档或仓库。
- 上述配置已通过最小合成调用及真实 Wiki 首跑（见 evidence/pi-transport.md、evidence/retrieval-pivot.md），尚无专家业务质量、负载和额度适用性结论。[智谱官方 FAQ](https://docs.bigmodel.cn/cn/coding-plan/faq.md)要求自建机器人使用标准 API 服务，不能假定 CC 的 Coding Plan 额度适用于 wikiBot；具体账户服务类型、端点及配额在阶段 0 核对。
- 领域访问资格为前提；普通成员与知识管理员使用固定能力模板，平台配置权限单独管理。服务端在 API、工具、作业执行与实际交付处核验当前授权和对象范围。
- 问答、工单、修订和发布使用独立对象和状态。业务结果、生成、完整性、交付与报告人确认分别记录。
- 快照与发布描述覆盖页面及允许的来源、金样例、模板、模型、检索、输出协议和评估基线。先固定描述，再加载其精确配置，单个答案不混用新旧版本。
- 复核绑定最终内容哈希；变更后重新复核。构建、评估、激活失败不改变现有线上版本。
- 激活、撤回、回滚使用共同领域锁及单调发布代际，检查基线、审批、当前权限和模型资格。撤回后允许从空指针创建修复版本，永久失效版本不可恢复。
- 来源写回以人工维护窗口为边界，记录基线、更正依据与部分写入恢复日志；无法保证单写者时人工合并并重新快照。
- 用户已提供广告 Wiki 本地目录，并确认通过一套 llm-wiki skills 更新。发布助手对接现有 Markdown 正文与受控技能维护入口，原始来源存档保持只读；具体技能定义、版本、更正材料保存和摄入方式在阶段 0 核实，独立副本验证后再落实来源写回。早期 nashsu/llm_wiki 桌面研究不作为运行依赖，完整设计与交接已同步修正。

### 可配置权限、表达标签和知识工作区（2026-09-27 用户确认）

- 领域访问资格和知识管理员由获准的平台配置人员管理；配置绑定领域与可信用户身份，不硬编码管理员姓名。知识管理员权限与 business/technical 表达标签分别保存；标签不授予领域访问、发布或平台管理能力。
- 用户可同时拥有 business、technical 标签。回答视角优先级为：本轮明确选择 > 用户主动保存的领域偏好 > 标签默认值（含 technical 时选 technical，仅 business 时选 business）> 领域默认值。解释深度仍沿用显式选择/已保存偏好/领域默认，不从标签推导新权限或熟练度。
- Wiki 根目录与来源适配入口按领域受控配置；真实目录只是一个实例。仅获准配置人员可更新绑定，普通成员请求不得传任意路径；更换根目录后重验绑定、稳定 ID、基线和路径边界，旧修订不能静默写入新目录。
- 配置变更应可追溯，使用当前授权及并发版本检查；授予/撤销资格在后续读取、作业及实际交付处重新核验。运行中的答案保留其表达配置快照；配置标签不能自动合并跨端私人历史。
- 验收至少覆盖：纯业务、纯技术、双标签、无标签、显式覆盖、撤销管理员、越域修改、普通成员自升权和 Wiki 目录切换。测试身份可先验证配置机制；真实公司身份、实际维护技能和业务批准仍分别验收，不以未指定固定姓名阻塞开发。

### 两轮访谈决定（由后续已接受决策修订）

| 决定 | 必须实现的外部行为 |
|---|---|
| Q1 检索式回答（ADR-0004 替代原 Q1） | 检索已发布页面，引用与协议校验；证据不足不编造，知识缺口不等于业务不适用 |
| Q2 多轮理解 | 当前可用历史用于指代与追问；对象切换或纠正以本轮为准，不把旧回答当当前知识 |
| Q3 可信恢复 | 恢复内容内部一致仍不足以开放；须核对当前可信授权、撤回状态和执行证据 |
| Q4 模型变更门禁 | 已知变化后暂停受影响新生成及使用旧评估的候选；新配置评估并发布后恢复 |
| Q5 限定支持范围 | 可先发布负责人批准的有限范围；金样例与人工核验覆盖承诺范围，范围外透明说明未覆盖 |
| Q6 历史有效性 | 每轮重验可用历史的授权、版本、模型复核和交付范围；当前页面为事实依据，不再维护类型化字段语义版本 |
| Q7 历史可见性 | 原受众已交付部分带待确认标记可看；未交付暂停、资格不明的进行中回答停止；新模型回归不自动批准旧答案 |

### 问答与交付

- 网页和企微采用自由文本提问与追问，不要求流程/对象/条件语法，不恢复 `/条件`、`/继续`。无检索命中明确返回知识缺口且不调用模型；有命中但不足以回答时说明不足或提出必要澄清，不编造完整操作建议。引用存在不等于语义正确，业务事实需专家评测。
- 当前链路为服务端受限页面检索加一次模型调用；pi-agent-core 多跳工具与嵌入检索留作后续，不是当前任务硬前提。默认请求期限为 15 秒（可配置），不延长重试/重连后的原始期限；该工程期限不改变 3 秒首段/10 秒整答联合 SLO。
- 先持久化有效块再交付；同一会话轮次串行执行，不同用户可并行。持久化租约和执行令牌拒绝旧执行者提交。
- 网页写请求以有范围的幂等键和请求摘要去重。企微以真实稳定入站消息 ID 去重；两个相同文本的真实请求不能擅自合并。
- 模型调用结果未知时原答案进入失败或不完整，用户显式重试产生新答案；不承诺供应方计算或外部投递恰好一次。
- 每 bot 一个连接拥有者；流式更新发送已校验累计正文，同一流等待一个回执，按 UTF-8 字节和最终回执判断完成。
- 首阶段 Bot 接入凭据已由用户提供，实际认证、租户、机器人类型及消息协议须通过阶段 0 验证；由受控运行时注入，认证帧和 Secret 不进入日志/评估证据。机器人连接身份与提问成员的领域资格、管理权限分别核验。
- 网页读取、重连和群引用均核验当前授权、有效性与原受众已交付范围；无法确认的投递保留 unknown，不能当作 acked。
- 状态变化、权限版本、处理结果和待发事件采用明确事务边界。审计与必要内容保留分别管理，删除会话不静默删除工单或发布记录。

### 流式、历史与评估的验收边界

- 模型增量、正文解码、校验、持久化、渠道 ACK 和客户端显示分别记录；只能将已通过当前协议、引用、版本及授权校验的正文外发。若完整 JSON 才能验证引用，则缓冲到最终校验，不为首段目标提前泄露未经校验正文。失败、取消、截断、协议降级和部分交付不得标完整成功。
- 历史限定同领域、同用户、同会话和原受众可用的已交付内容；不使用已撤回、模型待复核、未交付/未知交付或无权访问正文补充新生成。历史快照排队期间再次变更须在模型调用前检查；历史可供原受众带警示查看，不等于可用于新回答。
- 金样例对预期引用、关键内容/禁止结论或预期缺口作可检查判定，评估运行完成与质量判定分列；失败/未判定不能满足发布门禁。预期不由被测模型自行决定，人工核验及新质量阈值不得由开发者虚构批准。
- 原 SLO 仍为 ≥95% 普通请求联合满足有用首段≤3 秒、完整交付≤10 秒且成功；15 秒内完成而超过10秒的答案可在运行上完成，但不计 SLO 联合成功。真实 Wiki 少量 5.5–10.6 秒记录不是容量或达标证明。

### 交付范围与先决条件

受控试点必须完成三个广告业务主题各自批准范围内的知识回答与专家核验、两种视角与深度、两种领域角色、网页和企微单聊、基本工单、答案反馈、管理员 bot 修订及来源写回发布、撤回/回滚、模型变化门禁和可信恢复。

完整范围另交付受控群聊、完整来源与附件组合、工单合并/内部备注/附件、第二领域配置接入及对应组合验证。

模型端点与候选配置、企微 Bot 标识及 Secret、广告 Wiki 本地目录均已有用户输入。仍须验证适用的模型标准 API 服务与配额，以及 Bot 认证连接、实际消息协议和成员身份映射；Wiki 须核对实际维护工具、受控更正路径和首批批准内容，通过受控配置指定知识负责人并补齐真实问题样本，部署还需数据库和受控存储。缺外部输入的验证任务记录具体阻断；模拟结果不能关闭真实兼容性任务。后续实施任务按依赖推进，未获得所需先决证据不宣称可上线。

## Testing Decisions

### 已确认的测试边界

以应用对外业务行为为主要测试入口：认证请求或渠道事件进入系统后，观察返回内容、可查询业务状态、页面显示和渠道交付。覆盖持久化与异步执行；不对私有函数调用次数、内部对象排列等实现细节写镜像断言。

外部适配处采用窄边界：公司模型、企微和 llm_wiki 工作区可在确定性回归中替换为受控测试实现；阶段 0 和正式联调必须另跑真实接口。仓库已有应用集成回归和真实首跑记录，旧结构化流程测试及旧企微合成联调不代表新检索链路验收。

纯逻辑仅在检索预算、引用协议、历史可见范围和状态迁移存在大量边界组合时补充低层测试；关键结论仍需通过公开业务入口验证。浏览器端到端测试集中在成员问答、工单跟踪、管理员复核和历史警示等关键路径。

### 必须覆盖的行为

- 授权：跨域、他人对象、伪造角色、旧按钮、撤权后异步任务与群受众不明均被拒绝。
- 回答：检查金样例预期、错误引用、来源冲突、知识不足与澄清；完整指南由业务专家核对必要条件和步骤，不声称程序已证明分支穷尽。
- 上下文：同会话追问、客户切换、用户纠正、知识撤回/换模/未知交付、跨域跨人和旧回复注入；快照建立后、模型调用前再核验，历史不替代当前知识。
- 发布：两候选竞争、撤回抢先、旧回滚、空指针修复、修改后旧审批和模型待验证候选。
- 恢复：接收事务、模型调用、持久化、发送与回执之间注入故障；旧 worker 被拒绝，未知结果不重复执行业务。
- 历史：模型待复核的 GET、SSE、群引用、部分交付、未知回执、新模型回归及旧备份恢复。
- 来源：冲突、部分写入、重新导入、页面/金样例/配置同步、稳定 ID、引用与附件可追溯。
- 工单：明示登记、模型不可用仍可登记、幂等、本人范围、管理员处理、报告人关闭与重开、合并及内部内容隔离。
- 性能：测试前固定支持范围、分类、并发、答案长度、模型版本与配额；至少 95% 普通请求同时满足有用首段不超过 3 秒、完整交付不超过 10 秒及成功条件。超时、拒绝、系统中断和支持范围内失败不移出分母。
- 质量与效果：三流程至少 30–50 条专家核对真实题，另加权限/故障样本；至少 1,000 次普通请求测时延分布，不将重复运行题目当作泛化质量证明。自行完成操作通过反馈与抽样访谈确认。
