# 06：发布一条固定流程并供成员浏览

**What to build:** 管理员复核、评估并激活一条固定流程，成员通过稳定入口读取同一版本的完整原文和引用。

**Blocked by:** 01：验证公司模型的真实问答契约；05：维护者提交快照并查看最终差异。

**Status:** in-progress

**交付阶段：** 试点。依据为 2026-09-26 两轮访谈修订后的 wikiBot v0.4，设计约束及任务拆分已由用户的 implement 指令确认。

**用户故事：** US-02、US-08、US-11、US-14（实施规格编号）。

**外部前提：** 负责人批准的一条固定流程（优先新增代理商）、最小真实评估题与公司模型可用配置。

## Acceptance criteria

- [ ] 构建不可变正文/索引与 ReleaseDescriptor，固定知识、流程、模板、模型、检索、协议及评估配置；结果单独绑定描述哈希，避免循环哈希。
- [ ] 完整呈现 submitted→reviewing→building→evaluating→ready→active 的结果与失败原因；构建、评估或审批失败不改线上指针。
- [ ] 初次内容复核绑定最终内容，ready 后发布再次展示配置与评估；配置变化不能沿用不相符的评估通过记录。
- [ ] 激活从第一版起按统一领域/授权锁检查当前权限、基线指针与 epoch、审批、哈希和当前模型资格，事务写入指针、结果、审计及通知 outbox。
- [ ] 稳定入口仅绑定已创建领域；校验允许的知识主机、协议、重定向、响应大小与哈希，拒绝任意内网读取和跨域绑定。
- [ ] 成员可浏览已发布原文及版本化引用，未发布草稿不可见；助手离线仍可读取，不把模型故障等同于知识正文自动失效。
- [ ] 以真实模型配置完成最小评估并从成员页面验证一条固定流程；记录准确发布 ID 和描述哈希。

## 验证方式

公开发布/读取入口集成测试加真实最小评估；完整竞争、撤回和回滚反例在任务 17 强化。

验收结果须记录实际配置/版本、执行环境、预期与实得、证据及剩余阻断；未实现、未运行或外部前提缺失不能标为通过。用例集中于公开业务行为和真实适配契约，避免为内部实现细节建立镜像测试。

## 范围边界

仅固定流程的首次正常发布；不要为此复制后续候选、审批或指针实现。
