# 07：网页问答返回完整流程与可信引用

**What to build:** 成员在网页询问已发布固定流程，得到程序呈现的必需清单、模型补充解释和可核对引用；单步问题获得适当简答。

**Blocked by:** 06：发布一条固定流程并供成员浏览。

**Status:** in-progress

**交付阶段：** 试点。依据为 2026-09-26 两轮访谈修订后的 wikiBot v0.4，设计约束及任务拆分已由用户的 implement 指令确认。

**用户故事：** US-11、US-14、US-15、US-24（实施规格编号）。

**外部前提：** 已发布固定流程与代表性的完整指南、术语和单步问题。

## Acceptance criteria

- [ ] 服务端固定当前发布描述后检索并加载精确配置；回答保存实际模型、模板、偏好快照与引用版本，回答装配期间更新 active 不混合新旧配置。
- [ ] 完整流程的前置条件、材料、步骤、完成标准由批准节点确定性呈现；引用合法仍不能掩盖漏节点，完整性依据真实覆盖而非模型自报。
- [ ] 模型只补充有依据的解释，正文不能扩大工具权限；拒绝伪造引用、不受支持结论和未通过结构校验的块。
- [ ] 普通请求采用一次模型调用及原始 deadline；明确区别术语/单步解释与完整指南，不因截断而把指南改算成功简答。
- [ ] 接收时将业务请求、Answer 和 Job 持久化在同一事务，保存有效块后再外发；网页可查询答案与终态，初始路径保留幂等与重连契约。
- [ ] 通过成员网页完成问答与引用查看；缺知识、模型失败或没有有效块给出真实原因，不以空占位内容计有用首段。

## 验证方式

主要从认证问答入口和网页观察结果；覆盖 Q-01、Q-03，包含一次真实模型端到端演示。

验收结果须记录实际配置/版本、执行环境、预期与实得、证据及剩余阻断；未实现、未运行或外部前提缺失不能标为通过。用例集中于公开业务行为和真实适配契约，避免为内部实现细节建立镜像测试。

## 范围边界

多条件分支、受限复杂读取、对象跨轮、完善的崩溃注入分别由后续任务承担。
