# 21：完成受控试点验收并给出上线结论

**What to build:** 以固定范围、负载和版本验证一个广告领域的三流程、网页/企微单聊和维护闭环，形成可追溯的通过或阻断结论。

**Blocked by:** 19：部署后从可信状态恢复服务；20：三类广告流程通过真实知识评估。

**Status:** blocked

**交付阶段：** 试点验收。依据为 2026-09-26 两轮访谈修订后的 wikiBot v0.4，设计约束及任务拆分已由用户的 implement 指令确认。

**用户故事：** US-49、US-50（实施规格编号）。

**外部前提：** 试点负责人批准的用户范围、负载档位、公司模型配额、业务专家和值守安排。

## Acceptance criteria

- [ ] 验收前冻结试点支持范围、普通/复杂分类、模型描述、典型长度、并发、页数、领域数和配额；范围变更重新建立基线，不事后剔除失败。
- [ ] 至少 1,000 次普通请求统计联合成功：同一请求同时满足有用首段≤3 秒、完整交付≤10 秒和成功条件，联合比例≥95%；报告 P50/P95/P99、错误与未达标样本。
- [ ] 将空首段、引用只在末尾、半截流、超限、未知投递、支持范围内失败计入正确分母；不能用两项边际达标率代替联合结果。
- [ ] 三流程、角色/风格组合、网页/真实企微单聊、独立登记、反馈修订、主动维护、来源往返、最终复核和发布通知均有端到端证据。
- [ ] 选定范围的 Q/P/R/M/A/C/W 用例全部通过，A-04 等未启用功能明确列为未验收；不省略权限、流程完整性、并发与基本恢复。
- [ ] 结合任务 19 的实际环境演练验证上线检查、告警负责人、保留政策与回退处理；模型/企微/Wiki 任一真实契约未通过不得以模拟替代。
- [ ] 采集上线前专家答疑基线，准备明确用户反馈及抽样访谈，分别报告自行完成、工单解决确认/重开/复发；无追问或点赞不当作已完成操作。
- [ ] 给出证据目录、批准范围及阻断项；未通过时列可复现问题，修复后重验受影响项；通过验收不自动对全公司扩大开放。

## 验证方式

真实环境质量、故障、权限、负载和业务验收报告；这里只承诺完成验收工作，不预先承诺一定通过 SLO。

验收结果须记录实际配置/版本、执行环境、预期与实得、证据及剩余阻断；未实现、未运行或外部前提缺失不能标为通过。用例集中于公开业务行为和真实适配契约，避免为内部实现细节建立镜像测试。

## 范围边界

群聊、完整来源/附件、高级工单和第二领域不在试点完成声明内；完整范围以任务 26 为准。
