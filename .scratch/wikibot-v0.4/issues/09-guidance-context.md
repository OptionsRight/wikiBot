# 09：按咨询对象继承输入并按语义重确认

**What to build:** 成员同对象追问可复用有效条件，换对象或知识规则变化时只要求重新确认受影响条件。

**Blocked by:** 08：按支持范围澄清并选择唯一完整路径。

**Status:** in-progress

**交付阶段：** 试点。依据为 2026-09-26 两轮访谈修订后的 wikiBot v0.4，设计约束及任务拆分已由用户的 implement 指令确认。

**用户故事：** US-17、US-18、US-19、US-20（实施规格编号）。

**外部前提：** 具有对象切换、文案修改、字段语义修改及新增条件的已审阅流程样本。

## Acceptance criteria

- [ ] 已确认输入绑定用户/会话、流程及咨询对象；仅同流程同对象可继承，换客户/策略失效，对象不明先确认。
- [ ] 用户纠正条件后旧值立即退出有效输入；摘要、旧回复或检索结果不能重新把它升级为已确认值。
- [ ] 每个输入带批准字段语义版本；仅文案变化保留兼容值，含义/选项/适用条件变化重确认受影响字段，新增必要条件补齐。
- [ ] 每轮以当前知识版本重新计算分支；不沿用历史路径 ID 或旧清单，不把有效输入直接视为当前答案已完整。
- [ ] 页面与渠道共用该上下文契约；没有可信身份映射不跨端合并私人历史，也不跨不同客户传递条件。
- [ ] 演示相同对象追问、明确/含糊对象切换、纠正、纯文案更新、语义更新及旧摘要注入，用户能理解每次澄清原因。
