# 09：使用当前可用历史理解自由文本追问

**What to build:** 当前会话近期历史帮助理解指代和追问，每轮仍以当前有效页面为事实依据。

**Blocked by:** 08：知识不足、来源冲突与必要澄清。

**Status:** in-progress

**交付阶段：** 试点。依据为 2026-09-26 两轮访谈修订后的 wikiBot v0.4，设计约束及任务拆分已由用户的 implement 指令确认。

**用户故事：** US-17、US-18、US-19、US-20（实施规格编号）。

**外部前提：** 受控测试身份和页面/金样例可先验证机制；真实业务样本、公司身份和专家批准须另行取得。

## Acceptance criteria

- [ ] 历史限定同领域、同用户、同会话及原受众可见的已交付内容；跨端映射未验证不合并私人历史。
- [ ] 选历史与实际模型调用前均核验权限、知识撤回、模型待复核及交付状态；排队期间失效的历史不能随旧快照发送给模型。
- [ ] complete 生成不代表渠道已交付；未交付、unknown 及超出已确认范围的正文不带入新生成。已交付但模型待复核的历史仅可警示查看，不作为新生成依据。
- [ ] 历史有明确轮数/长度预算；仅供理解提问，不代替当前检索页面，不继承旧路径、旧清单或类型化字段语义版本。
- [ ] 明确换对象或更正以本轮为准；对象不明提出必要澄清，不把旧回复/摘要的条件升级为本轮已确认事实。
- [ ] 网页/渠道验证同对象追问、换对象、纠正、发布更新、撤回、换模、未交付与未知交付、跨域跨用户及排队后失效；不把模型抽样语义表现当确定性规则证明。
