# 14：跨端登记、反馈并关联最小工单证据

**What to build:** 成员在网页或企微单聊主动登记问题、反馈有权查看的答案并跟踪本人工单；处理人只看到定位所需证据。

**Blocked by:** 12：企微单聊接入同一问答与交付服务；13：成员登记独立问题并跟踪处理。

**Status:** in-progress

**交付阶段：** 试点。依据为 2026-09-26 两轮访谈修订后的 wikiBot v0.4，设计约束及任务拆分已由用户的 implement 指令确认。

**用户故事：** US-28、US-29、US-30、US-31、US-32、US-35（实施规格编号）。

**外部前提：** 代表性的知识错误、检索遗漏和表达问题样本。

## Acceptance criteria

- [ ] 企微复用网页的明示登记、本人查询/补充/确认关闭/重开和管理员处理入口；复杂内容可转认证网页，bot 回执真实编号与状态，模型离线不阻断基本登记。
- [ ] 反馈入口验证当前 answer 访问权限与领域，关联版本、描述哈希、模板、必要引用及最小允许内容快照；猜测他人答案 ID 不能创建泄露证据的工单。
- [ ] 明确区分反馈、独立问题和处理原因；模型分类只为建议，处理人可以基于已发布知识直接解答，不强制生成修订。
- [ ] 成员可从答案查看本人工单，管理员可定位问题与证据，但无权借关联读取其他会话、未提交上下文或附件。
- [ ] 反馈提交、证据与状态事件按幂等事务保存；重复操作返回真实原结果，旧幂等键也要检查当前资格。
- [ ] 反馈与会话采用独立保留规则；会话删除不静默破坏已保留的工单证据，同时不因此扩大可见范围。
- [ ] 在网页演示反馈→处理→公开结果→本人确认/重开，以及跨域、他人答案和额外私聊被拒绝。
- [ ] 网页与真实企微演示两端提交和查询；不同跨端幂等键不自动合并，相同请求重放不重复创建，投递未知不当作业务失败重做。

## 验证方式

应用业务入口的可见性和幂等测试，加真实企微登记、反馈、查询与状态通知；覆盖 A-02 的私人会话边界及 R-04 的工单通知。

验收结果须记录实际配置/版本、执行环境、预期与实得、证据及剩余阻断；未实现、未运行或外部前提缺失不能标为通过。用例集中于公开业务行为和真实适配契约，避免为内部实现细节建立镜像测试。

## 范围边界

成员建议不能直接写知识草稿或触发发布；后续由任务 15 建立管理员维护入口。
