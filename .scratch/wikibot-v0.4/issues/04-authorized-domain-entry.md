# 04：成员登录并进入有资格访问的领域

**What to build:** 平台配置人员开通一个待发布领域，成员通过公司身份进入该领域并看到准确的待发布状态；无资格者无法读取。

**Blocked by:** 02：验证企微身份、消息与交付协议。

**Status:** in-progress

**交付阶段：** 试点。依据为 2026-09-26 两轮访谈修订后的 wikiBot v0.4，设计约束及任务拆分已由用户的 implement 指令确认。

**用户故事：** US-01、US-02、US-03、US-04、US-05（实施规格编号）。

**外部前提：** 可用的公司认证集成、测试成员与管理员、开发数据库和运行环境。

## Acceptance criteria

- [ ] 从空工程建立可启动、可迁移的最小服务与网页，让真实认证成员看到授权领域及空知识状态；缺凭据/数据库不可用时拒绝业务访问。
- [ ] 平台配置权限独立管理领域创建、bot 凭据及授权；领域知识管理员没有隐含的平台权限。
- [ ] 服务端按租户、领域、操作与对象范围核验；伪造角色、跨域标识、技术视角和旧管理入口不能增加权限，拒绝可审计。
- [ ] 仅使用任务 02 验证过的稳定身份映射跨端关联；未验证映射不合并私人会话或偏好。
- [ ] 认证会话写操作具备适当的 CSRF/跨源约束；密钥仅存在受控服务端配置，日志不复制密钥或私人正文。
- [ ] 成员页面展示实际角色与知识可用状态；单测之外通过公开入口验证成员、管理员、无资格者与跨域访问。

## 验证方式

真实身份联调加应用入口的权限正反例；覆盖 A-01、A-02 的基础身份边界。

验收结果须记录实际配置/版本、执行环境、预期与实得、证据及剩余阻断；未实现、未运行或外部前提缺失不能标为通过。用例集中于公开业务行为和真实适配契约，避免为内部实现细节建立镜像测试。

## 范围边界

本任务不发布知识、不生成答案；空领域不能显示为已开通知识服务。
