# 17：并发发布、紧急撤回与安全回滚

**What to build:** 管理员在并发更新或错误知识事件中得到唯一发布结果，能够撤回并发布修复，网页和企微停止后续失效正文。

**Blocked by:** 12：企微单聊接入同一问答与交付服务。

**Status:** in-progress

**交付阶段：** 试点。依据为 2026-09-26 两轮访谈修订后的 wikiBot v0.4，设计约束及任务拆分已由用户的 implement 指令确认。

**用户故事：** US-38、US-39（实施规格编号）。

**外部前提：** 两个同基线候选、可回滚历史版本、真实企微测试通道与撤权测试主体。

## Acceptance criteria

- [ ] 激活、撤回、回滚共用领域锁、当前授权锁及单调 epoch；命令携带幂等键、预期基线、目标哈希及理由，命令重试不重复生效。
- [ ] 两个同 epoch 候选只有一个激活；旧基线待激活记录及迟到构建不能重新变 ready，旧审批/按钮在内容、权限或基线变化后失效。
- [ ] 撤回 active 后指针可为空并保持维护；新修复候选使用当前空指针基线和新复核评估合法发布，revoked 永不恢复。
- [ ] 回滚使用独立审批，核验当前基线、目标 retired 有效性、可用配置和当前模型资格；无安全目标保持维护。
- [ ] 网页重连、检索、工具读取与真正交给渠道 SDK 前检查当前授权/撤回；排队内容受阻，正常版本更新不混合单个答案。
- [ ] 已在途或已显示消息的跨系统限制如实记录；网页失效标记与企微稳定编号更正通知分别保留 acked/failed/unknown，测撤回传播时间。
- [ ] 通过成员可见结果证明故障/并发不会后写覆盖或复活撤回内容；审计、指针、命令结果及 outbox 保持事务一致。

## 验证方式

覆盖 P-01、P-02、P-03、C-01、A-03 的激活边界；真实通道观察撤回后的待发内容与更正通知。

验收结果须记录实际配置/版本、执行环境、预期与实得、证据及剩余阻断；未实现、未运行或外部前提缺失不能标为通过。用例集中于公开业务行为和真实适配契约，避免为内部实现细节建立镜像测试。

## 范围边界

不以数据库锁承诺已进入外部网络的消息可原子撤销。
