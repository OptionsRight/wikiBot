# 15：管理员通过 bot 发起并跟踪知识修订

**What to build:** 管理员在企微单聊主动修订知识或从工单发起修订，取得草稿编号、网页差异预览和真实的待写回状态。

**Blocked by:** 14：跨端登记、反馈并关联最小工单证据。

**Status:** in-progress

**交付阶段：** 试点。依据为 2026-09-26 两轮访谈修订后的 wikiBot v0.4，设计约束及任务拆分已由用户的 implement 指令确认。

**用户故事：** US-34、US-35（实施规格编号）。

**外部前提：** 有维护能力的测试管理员、脱敏更正依据及可访问的认证网页。

## Acceptance criteria

- [ ] 只有明确维护请求进入修订；管理员普通咨询仍是问答，普通成员伪造命令、角色、工具参数或旧按钮均无法创建/修改草稿。
- [ ] 草稿绑定目标页面、当前基线哈希、操作者、依据与影响范围；材料不足列缺口，不由模型编造业务规则。
- [ ] bot 支持主动创建、补充和查询；网页展示原文/拟改内容、来源、金样例与发布配置差异；每次更新使用幂等键和预期对象版本。
- [ ] 提交后进入受控写回队列，助手未领取时如实显示 sync_pending，不能把草稿保存、提交或批准说成已发布。
- [ ] 从工单创建的修订仅携带允许证据，关联关系不扩大工单/会话访问；处理人不能自动替报告人确认解决。
- [ ] 维护操作在执行处检查当前权限，旧消息/按钮在授权或内容改变后失效；来自群的维护请求仅引导到认证个人入口，不公开草稿。
- [ ] 真实 bot 演示主动维护和工单转修订两条路径；重放提交不生成重复修订。

## 验证方式

真实企微+网页联调，覆盖 A-01 与 A-02 的维护入口；自动化验证成员越权、旧版本冲突和幂等。

验收结果须记录实际配置/版本、执行环境、预期与实得、证据及剩余阻断；未实现、未运行或外部前提缺失不能标为通过。用例集中于公开业务行为和真实适配契约，避免为内部实现细节建立镜像测试。

## 范围边界

任务只交付可保存/提交/查询的修订；来源应用与实际发布由任务 16 完成。
