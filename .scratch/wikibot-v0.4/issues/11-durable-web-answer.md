# 11：网页回答在重试、断线和崩溃后保持可查

**What to build:** 网页重复提交、重连或取消仍指向准确答案；服务崩溃后不产生重复业务对象，也不拼接另一轮模型生成。

**Blocked by:** 07：网页自由文本问答与版本化引用。

**Status:** in-progress

**交付阶段：** 试点。依据为 2026-09-26 两轮访谈修订后的 wikiBot v0.4，设计约束及任务拆分已由用户的 implement 指令确认。

**用户故事：** US-24、US-25、US-42、US-44（实施规格编号）。

**外部前提：** 可重启入口/worker 的测试环境与可注入失败的模型适配器。

## Acceptance criteria

- [ ] 验证 Inbox/幂等请求、Answer、Job 接收事务的各崩溃窗口；同键同摘要返回原结果，不同摘要明确冲突，不因入站已写而永久丢任务。
- [ ] 同会话轮次串行，不同会话可并行；worker 租约与 fencing 拒绝旧执行者提交块、终态或投递任务。
- [ ] 校验块持久化后才能外发；网页 GET/SSE 重连按可交付范围重放同一答案，当前授权和撤回资格不因断线绕过。
- [ ] 模型结果未知时原答案 failed/incomplete；不自动第二次生成并接续原流。用户明确重试创建可追溯的新答案。
- [ ] 取消、超时、崩溃恢复保留原 deadline 与已交付事实，网页分开显示生成、清单完整性及交付结果；状态不会无限 pending。
- [ ] 连接、发送或回执未知以独立 Delivery 状态保存，旧/重复事件不能重新执行业务；终态与相关事件按事务规则提交。
- [ ] 覆盖持久化前后、租约失效、块保存、终态及取消竞态；观测记录可定位请求与作业但不泄露私密正文。

## 验证方式

从公开提交/取消/读取接口注入进程故障，覆盖 R-01、R-02、R-03；证明没有重复对象和错误完成。

验收结果须记录实际配置/版本、执行环境、预期与实得、证据及剩余阻断；未实现、未运行或外部前提缺失不能标为通过。用例集中于公开业务行为和真实适配契约，避免为内部实现细节建立镜像测试。

## 范围边界

不承诺外部模型计算恰好一次；真实企微回执处理由任务 12 验证。
