# 05：维护者提交快照并查看最终差异

**What to build:** 维护者手动提交一个领域的文本知识快照，管理员在网页查看最终正文、来源与流程结构差异。

**Blocked by:** 03：验证 llm_wiki 知识往返与来源更正；04：成员登录并进入有资格访问的领域。

**Status:** in-progress

**交付阶段：** 试点。依据为 2026-09-26 两轮访谈修订后的 wikiBot v0.4，设计约束及任务拆分已由用户的 implement 指令确认。

**用户故事：** US-06、US-07、US-08（实施规格编号）。

**外部前提：** 经批准的试点文本样本、领域维护者和受限助手凭据。

## Acceptance criteria

- [ ] 助手一次配对一个受控工作区，凭据限定领域；快照包含正文、来源、ProcedureSpec 与必要配置，使用稳定 ID 和内容哈希。
- [ ] 上传中断/重试得到同一候选或明确冲突；缺包、哈希错误、越域提交、危险路径及不允许的外链被拒绝，半包不进入可复核状态。
- [ ] 网页复核展示实际最终包及差异，审批绑定最终哈希；正文或结构改变后旧审批不再有效。
- [ ] 正文与流程结构可共同审阅，人工规则不能由模型建议自动成为批准规则；保留提交者、基线和状态原因。
- [ ] 显示最后提交、最后发布及待处理状态；助手离线不影响已发布知识，不把无法观察的离线改动显示为已同步。
- [ ] 通过完整提交、断点重试、越域拒绝、修订后重新复核的公开业务路径验证。

## 验证方式

真实小工作区导出联调，确定性应用集成测试覆盖上传恢复和内容哈希；先不激活候选。

验收结果须记录实际配置/版本、执行环境、预期与实得、证据及剩余阻断；未实现、未运行或外部前提缺失不能标为通过。用例集中于公开业务行为和真实适配契约，避免为内部实现细节建立镜像测试。

## 范围边界

首条路径限定已验证文本与来源摘录；完整格式和静态附件在任务 23。
