# 03：验证 llm_wiki 知识往返与来源更正

**What to build:** 用真实小工作区完成导出、改名、引用、来源更正和重新导入，证明平台可以保留稳定身份及更正依据。

**Blocked by:** 无任务依赖；外部前提另行核验。

**Status:** blocked

**交付阶段：** 阶段 0。依据为 2026-09-26 两轮访谈修订后的 wikiBot v0.4，设计约束及任务拆分已由用户的 implement 指令确认。

**用户故事：** US-06、US-36、US-37、US-47（实施规格编号）。

**外部前提：** 用户已提供本地广告 Wiki 目录，并确认通过一套 llm-wiki skills 更新。该目录有知识正文、来源材料及内容版本；还需技能安装目录或仓库地址、固定版本、首个批准流程及知识复核人。现有 Git 子模块指针目标缺失，内容版本不能冒充技能版本，已提供目录及维护方式不等于往返兼容性通过。

**实际维护契约：** 发布助手读取现有 Markdown 知识目录，更正通过已确认的 llm-wiki skills 维护流程受控应用。原始材料为只读存档，不假定可直接追加更正；读取技能定义后确定更正材料的独立保存与摄入约定。只读快照可先准备，往返实验使用独立副本和实际技能流程，早期桌面应用研究不作为依赖。

## Acceptance criteria

- [ ] 读取实际 llm-wiki skills 的定义，记录技能版本、可用位置、来源读取与更正约定；以真实技能维护路径验证，不能只改文件后声称完成维护往返。
- [ ] 记录目录与技能支持的操作，给出从维护入口到导出的完整说明；在线服务读取已发布知识包，不依赖每次请求运行维护技能。
- [ ] 验证页面稳定 ID、改名、内部链接、来源摘录和样例白名单静态附件；区分平台侧清单字段与 llm_wiki 原生能力。
- [ ] 用一条专家更正演示更正依据、来源修订、生成正文及再次导入后的保留结果；旧材料不能静默覆盖已确认更正。
- [ ] 演示独占维护窗口、基线变化、部分写入和恢复；无法保证单写者时进入人工合并并重新快照，不声称具备底层原子写入。
- [ ] 产出最小脱敏输入/输出、来源映射和失败证据；列出哪些格式与附件通过实验，未验证项留到完整范围任务。
- [ ] 确认助手可在专用记录中维护配置、映射与日志，无需修改维护技能的内部实现。

## 验证方式

真实工作区往返至少一次，维护者核对更正与引用；保留中断/冲突实验记录。

验收结果须记录实际配置/版本、执行环境、预期与实得、证据及剩余阻断；未实现、未运行或外部前提缺失不能标为通过。用例集中于公开业务行为和真实适配契约，避免为内部实现细节建立镜像测试。

## 范围边界

不开发通用爬虫、其他 Wiki 连接器或无人值守双向同步。
