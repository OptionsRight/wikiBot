# 19：部署后从可信状态恢复服务

**What to build:** 运维能部署并观测试点，在恢复旧备份后核对独立当前状态，安全处理旧作业，再按范围恢复开放。

**Blocked by:** 16：更正写回来源并经复核发布生效；18：模型变更暂停服务并标记历史答案。

**Status:** in-progress

**交付阶段：** 试点。依据为 2026-09-26 两轮访谈修订后的 wikiBot v0.4，设计约束及任务拆分已由用户的 implement 指令确认。

**用户故事：** US-23、US-43、US-44（实施规格编号）。

**外部前提：** 部署负责人确认数据库/对象存储/网络/密钥方案、保留政策、RPO/RTO 目标、独立当前授权与知识有效性依据。

## Acceptance criteria

- [ ] 提供可重复部署、迁移兼容检查、配置占位清单与就绪门禁；缺数据库、内容、索引、当前身份或服务资格时按受影响范围明确降级。
- [ ] 数据库备份与不可变包配套，索引按固定内容/配置重建；恢复期间暂停普通访问、发布、作业和外发，缺包/不一致不能开放旧缓存。
- [ ] 模拟备份之后撤权、撤回和模型变更：不能以备份内审计自证可信，使用独立当前证据核验授权、可服务版本及历史复核/投递状态。
- [ ] 恢复记录保存恢复点、证据覆盖范围、授权核对、版本哈希、模型/历史状态、当前可信确认者和开放时间；依据不足保持维护，签字不能复活已撤回内容。
- [ ] 失效旧 worker 资格并逐项核对旧任务执行证据；pending 不等于未执行，未知生成/发布/写回不自动重放，deadline 不重置。
- [ ] 就绪、作业积压/卡死、权限拒绝、知识撤回抑制、投递 unknown、来源冲突和联合 SLO 等有可定位观测与负责人；日志脱敏。
- [ ] 按已确认保留政策处理会话、偏好删除、工单证据、修订和审计；幂等墓碑覆盖重放窗口，撤回不等待缓存自然过期。
- [ ] 实际演练数据库恢复、索引重建、卡死任务接管和通知失败；报告实测恢复损失/耗时，不把待确认默认值当公司承诺。

## 验证方式

覆盖 R-05、R-06，演练已撤回/撤权的旧备份、部分缺包、旧待办和模型历史待复核；保存部署与处置证据。

验收结果须记录实际配置/版本、执行环境、预期与实得、证据及剩余阻断；未实现、未运行或外部前提缺失不能标为通过。用例集中于公开业务行为和真实适配契约，避免为内部实现细节建立镜像测试。
