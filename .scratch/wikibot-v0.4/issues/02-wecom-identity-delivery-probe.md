# 02：验证企微身份、消息与交付协议

**What to build:** 在真实测试租户走通单聊入站、企业身份映射和累计流式回复，并确认群受众是否具备可核验条件。

**Blocked by:** 无任务依赖；取得下列外部前提后可开始。

**Status:** in-progress

**交付阶段：** 阶段 0。依据为 2026-09-26 两轮访谈修订后的 wikiBot v0.4，设计约束及任务拆分已由用户的 implement 指令确认。

**用户故事：** US-04、US-05、US-26、US-27、US-45（实施规格编号）。

**外部前提：** 用户已于 2026-09-26 提供企微 Bot 标识和 Secret，作为第一阶段机器人接入输入；凭据值不保存在任务文档或仓库，仅由受控运行时注入。仍需实际验证凭据有效性、所属租户与 bot 类型/协议，并取得测试成员、公司 SSO/用户目录映射及测试网页身份。已收到配置不等于已认证连接或已通过协议验证。

## 第一阶段接入范围

用户明确第一阶段支持企业微信机器人。沿用已确认的受控试点范围，首先交付企微单聊问答、明示问题登记/反馈/跟踪，以及管理员 bot 发起知识修订；网页继续承接认证查看、长答案与最终差异复核。群受众能力在本实验中探查，正式群聊交付保留在任务 22。

本票负责验证真实接口，任务 12、14、15 分别完成单聊问答、跨端工单与维护入口。Bot 凭据用于机器人接入，成员身份映射、领域资格和管理员能力仍须分别核验，不能从持有 Bot 凭据推导成员访问权限。

记录当前已提供接入输入，但尚未建立真实连接、发送测试消息或验证回执。验证报告只保存脱敏标识、配置版本及结果，不记录 Secret、认证请求头或原始认证帧。

## Acceptance criteria

- [ ] 使用已提供的 Bot 接入信息完成真实认证连接，核对所属租户、机器人类型及实际协议，明确成功、认证失败和断线状态；只在受控运行时读取凭据，日志与证据脱敏。
- [ ] 验证可信入站身份、稳定消息 ID 和 SSO↔企微用户映射；不能验证的映射不合并私人历史，相同文本的不同真实消息保持独立。
- [ ] 记录单 bot 连接归属、重连与滚动更新行为；验证累计正文、同一流一个未确认更新、最终完成回执与迟到回执的实际约束。
- [ ] 测试 UTF-8 字节上限、多字节正文、长流程、回执丢失及发送结果未知；区分 acked、failed、unknown，不从发送成功推断最终完成。
- [ ] 确认主动通知、稳定业务通知编号和认证网页降级入口的实际可用性；无法可靠完成的能力写出限制与处置。
- [ ] 确认群成员范围及变更能否获得可信证据；未知受众禁用群答案，保留可验证单聊/网页，不以群实验失败阻断已验证单聊方案。
- [ ] 交付版本锁定、脱敏原始协议样例、失败样例和可重演步骤，为身份与渠道实现提供已验证契约。

## 验证方式

真实租户中执行身份正反例、连续更新、断线、回执缺失和正文超限实验；不以 SDK 单测替代。

验收结果须记录实际配置/版本、执行环境、预期与实得、证据及剩余阻断；未实现、未运行或外部前提缺失不能标为通过。用例集中于公开业务行为和真实适配契约，避免为内部实现细节建立镜像测试。

## 范围边界

不实现生产网关和全部群聊业务，不承诺无缝多实例接管。
