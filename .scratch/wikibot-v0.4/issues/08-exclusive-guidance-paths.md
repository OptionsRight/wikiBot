# 08：知识不足、来源冲突与必要澄清

**What to build:** 检索式问答区分知识不足和业务不适用，在事实不明确时说明缺口或提出必要澄清。

**Blocked by:** 07：网页自由文本问答与版本化引用。

**Status:** in-progress

**交付阶段：** 试点。依据为 2026-09-26 两轮访谈修订后的 wikiBot v0.4，设计约束及任务拆分已由用户的 implement 指令确认。

**用户故事：** US-09、US-10、US-11、US-12、US-13、US-16（实施规格编号）。

**外部前提：** 受控测试身份和页面/金样例可先验证机制；真实业务样本、公司身份和专家批准须另行取得。

## Acceptance criteria

- [ ] 无检索命中返回明确 KNOWLEDGE_COVERAGE_GAP，不调用模型，不自动创建工单；可提示主动登记。
- [ ] 有检索命中仍可能不足：不得把相关页面当作正确答案证明；回答说明不足或提出当前问题所需的澄清，不编造缺失步骤。
- [ ] “业务不适用”必须有当前发布依据；无法回答不等于业务不适用。来源冲突未裁决时不作确定操作建议。
- [ ] 澄清属于对话，不作为完整业务答案通过；模型自由文本仍受相同协议、引用和授权限制，不恢复字段模板或分支引擎。
- [ ] 测试前固定支持主题、普通请求口径及预期结果；承诺范围内检索失败/错误回答仍计失败，不事后缩小分母。
- [ ] 公开入口覆盖无命中、有命中但不足、歧义/缺条件、相互冲突来源、无依据不适用声明和知识中的提示注入；输出与题集预期对照判定。
