**What to build:** 对有分支的流程先确认必要条件，只有在批准支持范围内唯一命中完整路径时才给操作清单；复杂问题可在预算内补读依据。

**Blocked by:** 07：网页问答返回完整流程与可信引用。

**Status:** in-progress

**交付阶段：** 试点。依据为 2026-09-26 两轮访谈修订后的 wikiBot v0.4，设计约束及任务拆分已由用户的 implement 指令确认。

**外部前提：** 知识负责人批准的有限支持范围、分支与字段澄清模板；真实规则不能由开发者臆造。

## Acceptance criteria

- [ ] 建模批准支持范围、明确不适用条件及互斥完整路径；每条路径含完整必需节点，构建期检查范围内空洞与分支重叠并阻止发布。
- [ ] 运行时区分 true/false/unknown；多命中防御性停止，零命中区分规则缺口、范围外未覆盖和明确业务不适用，缺输入才问批准字段。
- [ ] 模型伪装 clarification 的自由操作建议不外发；澄清由服务端允许的字段模板呈现，澄清不被记为完整流程。
- [ ] 只允许在当前描述与授权范围内的只读工具；复杂请求最多两次模型调用、一轮工具读取并受原始 deadline 限制，预算耗尽返回不完整/缺口。
- [ ] 普通/复杂分类及支持范围在测试前固定；范围内配置空洞或失败仍计原普通请求失败，不事后缩小分母。
- [ ] 演示支持场景、范围外、明确不适用、缺条件、重叠、空洞与伪澄清；程序清单和解释不能混用不同分支。
- [ ] 正文与 ProcedureSpec 共同复核；一条正确引用无法为其他必需节点背书。
