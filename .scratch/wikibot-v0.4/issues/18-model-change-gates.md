# 18：模型变更暂停服务并标记历史答案

**What to build:** 登记已知模型变化后，受影响生成和旧评估发布立即受控；原受众仅能查看已交付部分并看到“模型验证待确认”。

**Blocked by:** 17：并发发布、紧急撤回与安全回滚。

**Status:** in-progress

**交付阶段：** 试点。依据为 2026-09-26 两轮访谈修订后的 wikiBot v0.4，设计约束及任务拆分已由用户的 implement 指令确认。

**用户故事：** US-40、US-41、US-42（实施规格编号）。

**外部前提：** 可控制的模型变更事件、受影响与可排除答案样本、已交付/部分交付/未知回执记录。

## Acceptance criteria

- [ ] 按部署、可观测版本、调用时间与变化依据界定影响；无法证明不受影响的相关答案进入待复核，不仅用通知到达时间划线。
- [ ] 变更登记、新调用准入及发布以状态版本可串行判定；新请求、已排队调用、第二次调用、旧评估候选和回滚均不能绕过门禁。
- [ ] 无法确认资格的进行中答案停止后续调用/迟到提交，无有效块 failed，有效块 incomplete；原 deadline 不延长，不保留无限等待状态。
- [ ] 已完成且已交付内容按原受众和已交付范围可查，GET/SSE/引用显著显示待确认；未交付正文暂停，unknown 不算已交付，不能通过重连补发。
- [ ] 保留历史生成及交付事实，待确认状态独立记录原因、变更事件和复核；网页标记与企微稳定编号通知可追踪。
- [ ] 重新评估并发布配置后恢复新服务，但不自动清除旧答案警示；知识原文在有效且授权时可看，基本登记不依赖模型。
- [ ] 由当前获准复核者确认错误时使答案正文失效并更正，知识撤回优先于历史可见性；禁止普通管理员绕过复核能力直接清除警示。

## 验证方式

覆盖 M-01 至 M-04，并在网页读取、SSE、企微发送、旧 worker 返回、发布/回滚竞态交叉验证；任务 22 补充真实群引用。

验收结果须记录实际配置/版本、执行环境、预期与实得、证据及剩余阻断；未实现、未运行或外部前提缺失不能标为通过。用例集中于公开业务行为和真实适配契约，避免为内部实现细节建立镜像测试。

## 范围边界
