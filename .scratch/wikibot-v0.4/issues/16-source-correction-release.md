## Acceptance criteria

- [ ] 助手领取时在线核验当前领域/工作区资格和租约，凭据只允许领取授权任务及上传，不授予发布权；撤权或过期不启动新受控写入。
- [ ] 维护者协调暂停 llm-wiki 技能摄入与其他编辑，预检查全部来源基线；复制前后哈希及目录一致才生成快照，不能依赖自身文件锁假定其他维护进程停止写入。
- [ ] 用带范围和负责人的专家更正记录保留旧结论沿革，通过任务 03 验证的技能入口更新页面；更正独立保存，遵守原始材料只读约定，重新摄入后人工核对更正仍在。
- [ ] 任务日志记录基线、暂存与结果哈希；冲突不覆盖新来源，部分写入停止自动处理并恢复/人工完成，syncing 超时或结果未知不直接重做。
- [ ] 正文条件/步骤变化同步更新 ProcedureSpec，经最终一致快照共同复核并回测原问题及相邻问题；旧审批或旧结构不能继续使用。
- [ ] 复用既有发布事务，只有实际激活才标 released 并返回 release ID；等待、冲突、blocked、失败均可从 bot/网页查询，旧线上版本保持真实状态。
- [ ] 知识变更类工单关联实际发布和回归结果后才可判定 resolved，未解决继续处理中；发布不自动关闭工单，通知失败只重试通知。
- [ ] 实际本地写入开始后撤权不能声称跨系统原子回滚：停止后续受控动作、记录已发生结果，最终上传/激活仍需当前授权。
