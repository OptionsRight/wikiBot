## 接入侧准备工作

- 在独立验证副本中试验，源 Wiki 保持原状。先做只读导出、链接解析与内容哈希，再验证改名、更正和重新导入。
- 建立知识页、来源与引用的稳定映射；正确处理当前 Wiki 的相对链接和跨维度 wikilink。助手的 manifest、发布配置与映射单独管理。
- 为一个流程整理支持范围、必要条件、材料、步骤和完成标准，生成候选 ProcedureSpec 交负责人复核，不能把页面“已验证”标记直接当发布批准。
- 默认仅提取批准的 knowledge 页面及必要来源摘录/白名单附件。排除 .git、客户端配置、缓存、临时目录和执行脚本；知识中的工具指令按内容处理，不获得执行权限。
- source-docs 现有约定为只读存档，更正如何持久化需结合实际 wiki-ingest/维护方式确定；不静默改原料，也不提前假设可以自动写回该目录。
- Git 指针缺失不妨碍只读内容与哈希盘点。需要 Git 操作时恢复原受控检出或使用完整验证副本，不在原目录执行 git init 来掩盖问题；不读取或输出可能含凭据的 remote URL。
- 在维护技能与实际工具路径明确后，运行其规定检查并保存结果；本轮目录检查不冒充 wiki-lint 通过。
