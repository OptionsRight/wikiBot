# ADR-0004：检索优先的回答与反馈闭环

日期：2026-09-26　状态：已接受

替代：[ADR-0001](0001-exclusive-procedure-paths.md) 的结构化路径方案；[ADR-0002](0002-verify-state-before-restoring-service.md) 的可信恢复与 [ADR-0003](0003-revalidate-known-model-changes.md) 的换模门禁继续有效。

## 背景

v0.4 设计（4.3）要求人工编制结构化流程清单（manifest 中的 procedures/branches/nodes），服务端查表生成必需清单、模型只补充解释，以此保证清单正确性与可审计性。实践中该结构的人工编制成本成为接入真实知识的主要阻塞：真实 Wiki 已有 161 页可用内容，但无人编制结构。

用户于 2026-09-26 决策：**可以容忍回答偶发不准，质量由既有反馈闭环管理**（答案反馈 → 知识工单（附答案证据快照）→ 修订 → 重新发布 → 关联解决）。该闭环与页面/发布绑定，不依赖流程结构。

## 决策

1. 知识包收缩为 `pages + 金样例问答 cases + config`；结构化 procedure 模型（inputs/branches/nodes/guidance 及分支穷举校验）整体移除，旧实现由 git 历史保留。
2. 回答路径：服务端中文词法检索（retrievalVersion "1"，CJK 二元组 + 标题加权 + 长度归一，top-K + 上下文预算）→ 单次模型调用组织回答（纯 JSON `{text, citations}`）→ 引用白名单校验；检索无命中时返回明确的 `KNOWLEDGE_COVERAGE_GAP`，不调用模型。
3. 发布门禁从"分支覆盖程序证明"改为"金样例问答评估 + 人工复核"；评估机制（幂等运行、modelEpoch 绑定、复核前必须完成）原样保留。
4. 答案期限 10 秒 → 15 秒（`ANSWER_DEADLINE_MS` 可配置）。实测 glm-5.3 整答 5.5–10.6 秒，10 秒边缘；此为对设计 7.1 SLO 的已记录偏差，真实负载下重新核定。
5. 渠道与网页一律自由文本提问；`对象/流程/条件` 语法与 `/条件`、`/继续` 指令移除。

## 后果

- 答案正确性不再有结构性保证，依赖：金样例评估（发布前）、引用白名单与固定版本展开（可追溯）、反馈闭环（事后修正）。模型编造清单的风险由"清单程序生成"转移为"引用校验 + 反馈频率"承担。
- 接入新领域成本降为"生成页面清单 + 写金样例"（`tools/manifest.ts` 一条命令起草）。
- 设计 4.2 的受限工具循环（pi-agent-core 多跳检索）与嵌入检索留作后续（retrievalVersion 升级位）；glm 首字 4–8 秒使多跳在当前期限内不可行。
- 群聊、附件、第二领域等原开放项不变。

## 2026-09-27 规格对齐说明

近期对话可帮助理解自由文本追问，但只能在当前授权、知识有效性、模型复核和已交付范围允许时使用；历史答案不升级为知识来源。流式生成不授权直接外发未经协议/引用验证的正文；完整 JSON 校验前的解析片段不能计为已验证首段。当前实现与此约束的差距由问答任务修复。

15 秒是默认请求终止期限，不是新的质量或性能验收阈值。原 95% 普通请求同时满足有用首段≤3 秒、完整交付≤10 秒及成功的联合 SLO 保留；是否修订须依据真实负载结果另行决定。金样例运行 complete 也不等于正确性通过，评估必须对照已定义预期记录判定，再由管理员复核。
