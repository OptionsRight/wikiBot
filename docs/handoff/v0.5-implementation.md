## 关键设计落实与边界

1. TS 单实例单写入连接保留原事务/幂等。Python 处理文件和指标，受进程树资源约束或评测截止时间监督，不连接 SQLite。Docling 不能联网下载模型；DeepEval 不加载公司凭证或 dotenv，不发送遥测。
2. SQLite 是批准、冲突、任务和候选的权威；sidecar 是可核验投影。完整清单先落盘、数据库后引用。已发布 bundle 固定事实/证据；活跃草稿的新更正不静默改旧回答。过期事实不从 mixed 页面全文绕过。
3. 事实提议和 Code Wiki 首版采用可核对的手工事实与确定性代码摘录，不让模型自己批准、合并范围或猜测跨文件业务关系。背景/反证保留为关联，发布支持集明确隔离。
4. 新协议使用闭合 NDJSON 正式块；序号、范围与 Claim/Evidence 关系检查后持久化，才能交付。V1 不可修复的模型输出报错，不再假造首命中引用。Pi 模型身份/停止原因在生成结束才返回，故 V2 暂在整次生成完成后提交正式块；预览不计为首正式块，不宣称流式 SLO 达标。
5. native PDF 无需权重并已实际验证；扫描/图片保守 partial。standard/OCR 已接入离线权重与摘要校验，尚需真实权重和扫描业务样本验收。文档解析不是电子表格计算引擎。
6. DeepEval 真实指标在隔离环境执行，公司调用经 Pi。影子仅不按未经校准的分数阻断，完整性/版本/超时等始终阻断。blocking 必须绑定人工正反例校准，新题集或风格克隆不能沿用旧完整题集报告。
7. 原共享默认密码移除；显式存量密码迁移为 scrypt，新本地密码经平台版本化配置，演示随机生成。生产仍用现有 OIDC/领域资格。
